
1) FROM maven:3.9.9-eclipse-temurin-21 AS build
Базовый образ содержит и Maven, и JDK 21 (Eclipse Temurin — открытая сборка OpenJDK). AS build даёт этому этапу имя, на которое можно будет сослаться позже.
Этот образ довольно тяжёлый (сотни МБ — сам Maven, весь JDK с компилятором и т.д.), но это не страшно, потому что он не попадёт в финальный образ.


2) -pl event-manager ("project list") — собрать именно модуль event-manager (а не все модули репозитория).
   -am ("also make") — вместе с ним собрать и все модули, от которых он зависит (в твоём случае это event-common,
        откуда берётся NotificationPayload и другие общие DTO/классы).
        Без -am сборка event-manager упала бы с ошибкой "не могу найти event-common в локальном .m2 репозитории", потому что этот модуль ещё нигде не установлен.
   package — Maven-фаза, которая компилирует код, гоняет тесты (обычно) и упаковывает всё в .jar.

3) WORKDIR /app
   COPY . .

   WORKDIR создаёт (если её нет) и переключается в директорию /app внутри контейнера — все последующие команды выполняются относительно неё.
   COPY . . копирует весь контекст сборки (то, что ты передал в docker build, обычно весь корень репозитория — судя по context: . в docker-compose) внутрь образа.
   Это значит копируется вообще всё: event-manager/, event-notificator/, event-common/, корневой pom.xml и т.д. — весь multi-module Maven проект целиком, а не только нужный модуль.

4) Результат — в event-manager/target/ появляется готовый исполняемый .jar (собранный через spring-boot-maven-plugin, который упаковывает не только твой код, но и все зависимости внутрь одного "fat jar").

5)FROM eclipse-temurin:21-jre

  Новый, отдельный базовый образ — обрати внимание, это уже не maven:..., а eclipse-temurin:21-jre. jre (Java Runtime Environment),
  а не jdk — то есть внутри нет компилятора, нет Maven, нет ничего лишнего для сборки — только то, что нужно запускать уже скомпилированный байткод.
  Это значительно меньше по размеру.

6) ENTRYPOINT ["java", "-jar", "app.jar"]
   Команда, которая выполняется при старте контейнера — обычный запуск Spring Boot приложения через java -jar
